# ADR-0002: 値を返す MATCH と副作用を伴う DISPATCH をマクロ名で分ける

- **状態:** 採用
- **関連:** [C-08](../constraints.md#c-08)

## 文脈

variant ごとの処理には2種類ある。「ペイロードを受け取って値を返す純粋な変換」（面積計算、分類、整形）と、
「ペイロードに加えて共有コンテキストを書き換える副作用」（コマンド実行）である。

`DEFINE_SUM_MATCH` を拡張して「ctx ありでもなしでも使える」万能マクロにする案もあった。

## 決定

`DEFINE_SUM_MATCH`（戻り値あり・ctx なし）と `DEFINE_SUM_DISPATCH`（戻り値 void 固定・ctx あり）を
別マクロとして分ける。

## 根拠

万能マクロにすると、**呼び出し側がマクロ定義を読みに行かないと「今回は ctx が要るかどうか」を
判断できない**。契約（シグネチャ）が異なるものをマクロ名レベルで分けることで、呼び出し箇所を
見ただけで契約がわかる状態を優先した。関数命名の一貫性より責務分割を優先した例である。

## 帰結

- ロックフック（[ADR-0003](./0003-lock-hook-injection.md)）は DISPATCH にだけ付ければよくなった。
  MATCH は戻り値を呼び出し元が受け取ってから自分のスコープで処理するため、ライブラリ内部での
  ロックが必要になる想定がない
- `DEFINE_SUM_MATCH` に `RetType = void` を渡す誤用が生まれた。`case ...: return handler();` が
  void を返す関数呼び出しになり ISO C 6.8.6.4 違反になる（[C-08](../constraints.md#c-08)）。
  void 用途は DISPATCH を使うこと
