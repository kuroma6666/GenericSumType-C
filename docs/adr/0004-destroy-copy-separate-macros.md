# ADR-0004: 解放・コピーを DISPATCH の流用ではなく専用マクロにする

- **状態:** 採用
- **関連:** [C-03](../constraints.md#c-03)

## 文脈

variant が heap 確保された文字列やバッファなどのポインタ資源を持つ場合、解放とディープコピーが要る。
これも「variant ごとに処理を振り分ける」という点では `DEFINE_SUM_DISPATCH` と同じ形をしている。
`CtxType` を `void` 扱いにするなどして流用することも検討した。

## 決定

`DEFINE_SUM_DESTROY` と `DEFINE_SUM_COPY` を専用マクロとして独立させる。

## 根拠

デストラクタは「共有状態への書き込み」ではなく「**その variant 自身の後始末**」という別の関心事である。
シグネチャの形が似ていることと、責務が同じであることは別問題である。ctx を持たない専用マクロに
することで、呼び出し箇所を見ただけで「これは資源の後始末であって状態遷移ではない」と読める。

`DEFINE_SUM_COPY` は source 側を `const NAME *` / `const TYPE *` で受ける。コピー元を書き換えない
ことがシグネチャから読めるため。

## 帰結

- 資源を持たない variant にも全 variant 分のハンドラを渡す必要があるため、
  `SUM_DEFINE_NOOP_DESTROY` / `SUM_DEFINE_IDENTITY_COPY` という定型生成ヘルパが要る
- **呼び出し忘れ自体を防ぐ仕組みはない。**「呼べば網羅的に処理される」ところまでが保証範囲であり、
  「呼ぶこと自体の強制」は対象外（[C-03](../constraints.md#c-03)）
