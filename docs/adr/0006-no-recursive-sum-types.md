# ADR-0006: 再帰的な直和型は対応しない

- **状態:** 採用
- **関連:** [C-04](../constraints.md#c-04)

## 文脈

`enum List { Cons(i32, Box<List>), Nil }` のように自己参照する直和型は、連結リストや構文木を
表現するのに要る。C のマクロで再現できないかを検討した。

## 決定

**対応しない。**「未実装」ではなく意図的なスコープ外とする。

## 根拠

**言語仕様上の制約であり、マクロ実装の都合ではない。** ISO C 6.7.2.1 により、struct-declaration-list の
メンバには不完全型を置けず、struct/union 自身はその定義（`}`）が終わるまで不完全型として扱われる。
したがって `union { ...; List self; }` のような値埋め込みは規格上そもそも構文として成立せず、
`List *self` のようなポインタ経由に限られる。

ポインタ経由にすると heap 確保・解放・所有権管理をすべて手動で書くことになる。
再帰的データ構造の安全な表現（所有権とドロップ順序の保証）は Rust の型システムが得意とする領域であり、
C のマクロで無理に再現すると GC / 所有権チェッカーの車輪の再発明になって実装・保守コストに見合わない。

## 帰結

- 再帰構造が必要な場面では Rust、あるいは既存の C の侵入型データ構造ライブラリを使う
  （[requirements.md の採用すべきでない状況](../requirements.md#採用すべきでない状況)）
- `TYPE` に `struct Node*` を渡して手動で管理すること自体は妨げないが、その場合ライブラリが
  提供するのは tag の管理だけであり、所有権については何も保証しない
