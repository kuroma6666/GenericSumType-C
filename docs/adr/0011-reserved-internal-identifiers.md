# ADR-0011: 生成コードの内部識別子を `sum_*_` の予約名に限定する

- **状態:** 採用
- **関連:** [G-020](../GUARANTEES.md#g-020), [C-12](../constraints.md#c-12)

## 文脈

生成される関数の仮引数は当初 `self` / `ctx` / `v` / `NAME_on_<tag>` / `NAME_copy_<tag>` という名前だった。
利用側が同名の大域変数や関数を持つと（`static Ctx ctx;`、ハンドラを `Cmd_on_heal` と命名する等）、
生成関数の仮引数がそれを隠し、`-Wshadow` が警告する。`-Wshadow` は `-Wall -Wextra` に含まれないが、
名前の再利用を禁じる規約（ESCR M1「名前を再利用しない」）を持つ組込みプロジェクトでは
`-Wshadow -Werror` の運用が一般的で、その環境では `DEFINE_SUM_*` を呼んだ時点でビルドが壊れる。
生成コードの仮引数名は API に現れないため、利用側には回避のしようがない。

## 決定

生成コード内のローカル識別子（仮引数・ローカル変数）はすべて **`sum_` で始まり `_` で終わる名前**にする。
`sum_self_`, `sum_ctx_`, `sum_value_`, `sum_on_<tag>_`, `sum_copy_<tag>_`, `sum_handled_` など。
利用側はこの形の識別子を定義しないことを契約とし、ヘッダ冒頭と
[api_reference.md 10節](../../api_reference.md#10-内部マクロ直接呼び出さないもの) に明記する。

## 検討した代替案

| 案 | 不採用の理由 |
|---|---|
| そのまま（利用側が名前を避ける） | 仮引数名は API に現れず、利用側が知りようがない。`ctx` / `self` は利用側で最も自然な名前であり衝突が現実的 |
| `__sum_self` のような下線始まりの名前 | 下線で始まる識別子は ISO C 7.1.3 で処理系に予約されている。ライブラリが使ってはならない名前空間 |
| 生成コードに `_Pragma("GCC diagnostic ignored \"-Wshadow\"")` を埋め込む | 利用側が選んだ警告をライブラリが黙らせる形になる。衝突そのものは残るため根本対処にならない |

## 帰結

- 生成コードのローカル識別子に `sum_*_` という目印が付くため、マクロ展開結果を読むときに
  「利用側の名前」と「生成された名前」を区別しやすくなる（[C-12](../constraints.md#c-12) の緩和）
- 仮引数名が `sum_on_<tag>_` になっても、Clang の型不一致診断に引数名が出る際に「どの tag のハンドラか」は読める
- 利用側が `sum_*_` 形の識別子を大域に定義した場合は `-Wshadow` が出る。これは契約として文書化するだけで、機械検査はしない
- `self` / `ctx` / `v` / `NAME_on_<tag>` / `NAME_copy_<tag>` を大域に持つ TU が `-Wshadow` を error に昇格しても
  通ることを [G-020](../GUARANTEES.md#g-020) で機械検査する
