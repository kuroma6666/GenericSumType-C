# ADR-0008: `_Generic` でコンストラクタを型から選択する（C11 以降）

- **状態:** 採用
- **関連:** [G-008](../GUARANTEES.md#g-008)〜[G-010](../GUARANTEES.md#g-010), [G-017](../GUARANTEES.md#g-017), [C-01](../constraints.md#c-01)

## 文脈

`DEFINE_SUM_TYPE` が生成するコンストラクタ `NAME_new_<tag>()` は、呼び出し側が tag 名
（`i` / `s` / `f` 等）を正しく覚えて綴る必要がある。これを減らしたい。

関数テーブル方式（homogeneous function pointer table）も検討したが、全ハンドラを共通シグネチャに
揃える必要があり、[ADR-0001](./0001-x-macro-code-generation.md) の型安全性（渡し忘れ検出・順序取り違え検出）を
失う退行になるため不採用にした。

## 決定

C11 の `_Generic` を使い、渡した値の**型だけ**からコンストラクタを自動選択する
`DEFINE_SUM_NEW_GENERIC` / `SUM_NEW` を、**オプトイン機能として**追加する。
`__STDC_VERSION__ >= 201112L` でガードし、C99 ビルドでは存在しない扱いにする。

## 根拠

記述量を減らしつつ、2つの型安全性（渡し忘れ・順序取り違え）をどちらも犠牲にしない。
むしろ **[C-01](../constraints.md#c-01) の不変条件（variant 間でペイロード型が重複しない）を
新たに機械検査できる**という副次効果がある。`_Generic` は連想リストに互換な型が2つあると
ISO C 6.5.1.1 の制約違反となり診断が要求されるためである。

## 検出タイミングを定義時点まで前倒しする

当初は `SUM_NEW` を実際に呼んだ箇所でしか重複が検出されなかった。`DEFINE_SUM_NEW_GENERIC` は
補助の型・関数を生成するだけで `_Generic` 自体を展開しないためである。

これを解消するため、`DEFINE_SUM_NEW_GENERIC` にプレースホルダ型を実引数とする probe 関数を
生成させ、その場で `_Generic` を1回強制展開するようにした。プレースホルダは必ずマッチするので
実行時の意味はないが、**連想リストの重複診断は展開時点で発火する**。
結果として `SUM_NEW` を一度も呼ばなくても定義時点で落ちる（[G-009](../GUARANTEES.md#g-009)）。

## 帰結

- **`NAME_new(x)` のような専用マクロは生成できない。** C のプリプロセッサはマクロ展開結果から
  新しい `#define` を起こせないため、`SUM_NEW(NAME, VARIANTS, x)` と毎回明示することになる。
  他の `DEFINE_SUM_*` と一貫しない非対称性である。
  ただし利用側が `#define NAME_new(x) SUM_NEW(NAME, VARIANTS, x)` と自分で1行書くことは
  妨げられておらず、これが推奨イディオムである
- **型の完全一致が必要。** 暗黙の型変換に頼れず、ポインタが指す先の const 有無も別の型として
  扱われる（`char*` と `const char*` は別キー）。ペイロードを専用 struct でラップしていれば実害はない
- **C99 では機械検査が働かない。** 同じ設計ミスが C11 では落ち C99 では通る
  （[G-017](../GUARANTEES.md#g-017) と [G-018](../GUARANTEES.md#g-018) の対比）
- この機能を使うファイルを C99 の CI ジョブに含める場合、ファイル自体を `__STDC_VERSION__` で
  自己ガードする必要がある
